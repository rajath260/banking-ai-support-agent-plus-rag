# RAG Part 3: Vector storage and semantic retrieval

## Why do we need a vector store?

The embedding model converts each text chunk into a numerical vector. A vector store persists those vectors alongside the original text and metadata, then finds vectors close to a query vector.

This project uses Chroma in local persistent mode. It stores data on disk in the configured directory instead of requiring a managed cloud database.

## Retrieval flow

1. Load and chunk the fictional FAQ documents.
2. Generate an embedding for every chunk with the same local embedding model.
3. Upsert each chunk, its vector and metadata into a Chroma collection.
4. Embed a customer's question with that same model.
5. Ask Chroma for the nearest vectors.
6. Pass the returned text chunks to the answer-generation step.

The vector store does not generate embeddings itself in this project. Keeping embedding generation separate means we can change storage technology without rewriting the model adapter.

## Chroma collection

The default collection is named `banking_faq` and uses cosine distance. Each record stores:

- `id`: stable identifier based on source filename and chunk index.
- `document`: original chunk text.
- `embedding`: numerical vector generated by Sentence Transformers.
- `metadata`: source filename and chunk index.

The implementation uses `upsert`, so indexing the same source/chunk identifier again updates that record instead of creating a duplicate.

## Distance versus similarity

Chroma returns a cosine **distance** for this collection. Smaller distances indicate closer vectors and therefore a better match. The returned value is not a probability or a confidence percentage. A distance of 0.12 must not be described as a 88% confidence score.

## Install and test

Chroma is an optional RAG dependency:

```powershell
pip install -r requirements-rag.txt
python -m pytest -v
```

The unit tests inject a small fake collection. They do not require Chroma, download an embedding model or call a hosted inference API.

## Local persistence

The default storage directory is `data/chroma`. Chroma creates and maintains its local database files there. Treat this directory as application data: back it up if the indexed collection matters, and do not commit generated database files to Git.

## Production considerations

For a real banking system, evaluate authentication and authorization, encryption, backups, retention, tenant isolation, data residency, auditability, monitoring, index rebuilds and disaster recovery. Retrieved text must still be checked for relevance and access permissions before it is sent to a model. Vector similarity is a retrieval signal, not an authorization decision.
